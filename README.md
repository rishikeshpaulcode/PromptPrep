# Quiz Reel

An endless, AI-generated quiz feed. Pick a topic, add a short focus, and keep answering one multiple-choice question at a time until you decide to stop.

> **Status: work in progress.** The backend is almost complete. The frontend has not been started yet. This README describes both what exists today and what is planned.

## Overview

Quiz Reel presents questions the way a short-video reel presents clips: one question per screen, instant feedback after each answer, and a **Next question** button to move on. Questions are generated by an LLM (Google Gemini via LangChain) in batches and cached per session, so the feed never runs dry.

This is an open-source project built with two goals:

1. A useful, fun quiz experience.
2. A learning vehicle for building a scalable system following industry-standard practices. Design choices are documented so contributors can see *why* things are built the way they are.

## Features

**Available in the backend today**

- Session creation with a chosen topic and difficulty
- Batch question generation with structured LLM output
- Background top-up of the question pool when it runs low
- Answer checking with per-question explanations
- Score and counters tracked per session
- Session summary endpoint

**Planned**

- Curated, nested topic tree with a freeform focus (see [Topic Selection](#topic-selection))
- Skip option
- React frontend
- Rate limiting and abuse protection
- Session expiry (TTL)
- Async backend
- AI-generated session feedback and timing statistics
- Persistent cloud database for history and accounts (after v1)

## Quiz Rules

| Rule | Behavior |
|---|---|
| Question format | Multiple choice, exactly 4 options, one correct answer |
| Difficulty | Chosen at the start (easy / medium / hard) and fixed for the whole session |
| Scoring | +4 for a correct answer, -1 for an incorrect answer |
| Skipping | Allowed. Skipped questions do not affect the score |
| Re-answering | Not allowed. Each question can be answered (or skipped) only once |
| Ending | The quiz is endless; the user ends it manually and sees a summary |

### Topic Selection

Users choose from a curated, nested topic list and then add a freeform focus:

```
Physics  >  Laws of Motion  >  "test me on the concept of acceleration"
 (curated)     (curated)               (freeform text)
```

The freeform text is checked against the selected topic and subtopic. If it does not match, it is rejected and the user is asked to enter it again.

## Architecture

```
 Browser (React)
      |
      |  HTTPS, cookie-based session
      v
 FastAPI backend  ------>  Redis        (session state, question pool)
      |
      +----------------->  Gemini API   (question generation, topic validation)
```

Key ideas:

- **Anonymous sessions.** A session ID is stored in an HTTP-only cookie. Session state lives in Redis.
- **Question pool.** Questions are generated in batches. When the number of unseen questions falls below a threshold, a new batch is generated in the background so the user never waits.
- **Answer keys stay on the server.** The client receives only the question text and options. Correctness and explanation are returned after an answer is submitted.
- **Separate deployment.** The frontend and backend are deployed independently.

A fuller architecture write-up and decision records will be added as the design is finalized.

## API

Endpoints currently implemented:

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/init_new_session` | Create a session (topic, difficulty) and set the session cookie |
| POST | `/api/init_new_quiz` | Generate the first batch of questions |
| GET | `/api/get_next_question` | Get the next question (without the answer) |
| POST | `/api/check_answer` | Submit an answer; returns correctness and explanation |
| GET | `/api/get_session_summary` | Get final results for the session |

Planned: topic list endpoint, skip endpoint. Endpoint names and shapes may change as the API contract is finalized.

## Getting Started

> The project is under active development, and setup steps may change.

**Prerequisites**

- Python 3.11+
- A running Redis instance (default: `localhost:6379`)
- A Google Gemini API key

**Backend**

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install fastapi uvicorn redis langchain-google-genai python-dotenv pydantic
```

Create a `.env` file in `backend/` with your API key:

```
GOOGLE_API_KEY=your_key_here
```

Run the server:

```bash
uvicorn main:app --reload
```

A proper dependency file, `.env.example`, and Docker setup are on the roadmap.

## Design Decisions

| Decision | Choice |
|---|---|
| Difficulty | Fixed per session, not adaptive |
| Topic input | Curated nested list plus freeform focus that must match |
| Mismatched focus text | Rejected; user asked to re-enter |
| Skipped questions | Not scored |
| Backend deployment | Separate from the frontend |
| Repository layout | Single monorepo |
| Persistence in v1 | Session data only; database comes later |

Open questions still being decided: how to avoid duplicate questions, whether to share a question bank across users, frontend tooling, and session length limits.
